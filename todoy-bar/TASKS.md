## 날짜 경계 4시 + 이월 유실 봉합 (2026-08-12, 세션847 창A)

**증상** — 8/12 굿모닝에서 `setup` 출력이 `[]`, 어제 미완료 8건이 통째로 유실. 수동 이월로 넘겼다.

**원인 둘** (하나는 8/3에 발견해 놓고 안 고친 것)
- `render`가 `ensure_file`을 불렀다. 플러그인이 5초마다 부르므로 **자정 00:00:00 렌더가 빈 오늘 파일을 낳고**, 아침 `setup`이 `[ ! -f "$FILE" ]`에서 걸려 이월을 건너뛴다. 화면 그리는 코드가 데이터를 만들고 그 데이터가 다음 동작의 조건을 바꾸는 구조.
- ⚠️ **SwiftBar가 자정까지 살아 있어야 터진다.** 앞선 13일치 파일 중 00:0x 생성은 하나도 없었고 전부 첫 `add` 시각에 태어났다. 8/11 굿모닝 재시작 인스턴스가 19시간을 버티고 자정을 넘긴 것이 8/12에 처음 터진 이유 — **SwiftBar 안정성이 올라갈수록 더 자주 나는 사고**다.
- 그리고 자정 경계 자체가 피터공 하루와 어긋나 있었다(자정 넘겨 일하는 날이 잦다).

**고친 것 셋** (SPEC 먼저 → 코드)
- [x] SPEC — 「날짜 경계 = 새벽 4시」·「읽기는 쓰기를 하지 않는다」 절 신설 + `setup` 항 멱등 명세
- [x] `TODAY="$(date -v-4H +%F)"` — 00:00~03:59는 아직 어제. **경계가 사건이 아니라 계산식이라 4시에 컴이 꺼져 있어도 성립**(굿바이 리셋·4시 크론을 택하지 않은 이유)
- [x] `render`에서 `ensure_file` 제거 — 없으면 `[]` 출력만
- [x] `setup` 멱등화 — 조건을 「파일 없음」에서 「오늘에 같은 `text`가 없는 것만 덧붙임」으로. 실제로 물어야 할 것은 «이월을 아직 안 했는가»였고, 파일을 먼저 만드는 손은 렌더만이 아니다(굿모닝 전 `add`도 같은 문)

**검증 (2026-08-12, 샌드박스 사본 — 실데이터 무접촉)**
- `bash -n` 통과
- ①`render`가 오늘 파일을 안 만든다 ②자정이 만든 빈 `[]`가 있어도 미완료 3건 이월(완료 1건 제외·시간/횟수 초기화·`carried=true`) ③`setup` 3회 연속 → 3건 유지(중복 0) ④굿모닝 전 손수 추가분이 있어도 이월 정상 ⑤같은 텍스트 중복 유입 0
- 날짜 산술 실측 — `03:59→전날` / `04:00→당일` / `05:00→당일`(밤새 꺼져 있었어도) / `02:00→전날`
- 실데이터 회귀 — 8/12 파일 12건 그대로, 메뉴바 `오늘0/12` 정상 렌더
- ⚠️ 미검증(시간이 지나야 확인됨): 실제 자정 통과 · 4시 통과 시점의 파일 갈림. 8/13 굿모닝에서 `setup`이 오늘분을 정상 이월하는지가 첫 실전 확인

## 완료 항목 접기 — 지우지 말고 접는다 (2026-08-25, 세션981 창D)

**요청** — 피터공: *"todoy에서 완료된 내용은 지금 너무 항목이 길고 넘어온 것도 많으니 아카이브 지금 해줄 수 있어?"*

**먼저 손으로 해보고 알게 된 것** — 완료 4건을 `data/archive/2026-08-25.json`으로 옮기고 오늘 파일에서 뺐더니 목록은 15 → 11로 줄었는데 **메뉴바 카운터가 `오늘4/15` → `오늘0/11`이 됐다.** 완료 항목이 진행률의 **분자**라서, 파일에서 덜어내면 "오늘 뭘 했다"는 신호가 같이 사라진다. 하루치 JSON이 「메뉴바에 보이는 것」과 「그날의 기록」을 겸하는 구조라 생긴 일이다. → 아카이브 되돌리고(4건 복원, 15건 원상), `archive` 명령은 만들지 않기로.

**진짜 원인은 완료분이 아니었다** — 오늘 15건이 **전부 `carried=true`**였고 8/24 파일과 텍스트가 한 글자도 다르지 않았다. 오늘 새로 넣은 항목이 0건. 즉 **보기의 문제(완료분이 자리를 차지한다)와 이월의 문제(목록이 안 늙는다)가 한 증상으로 뭉쳐** 있었고, 접기는 앞엣것만 닫는다.

**고친 것** (SPEC 먼저 → 코드)
- [x] SPEC §컴포넌트 2 — 「완료 항목은 지우지 않고 접는다」 절 신설 + 「하루치 파일에서 덜어내는 명령은 만들지 않는다」 명시
- [x] `swiftbar-plugins/todoy-bar.5s.sh` — 본 목록은 `select(.done==false)`만 그리고, 완료분은 구분선 뒤 `☑ 완료 {N}건` 한 줄 + 서브메뉴(클릭 = 완료 취소, 첫 줄에 회색 안내). 미완료 0건이면 `오늘 할 일 전부 완료` 회색 한 줄
- [x] 데이터·`todoy.sh`·`sync.py`·편집창 무변경 — 프런트 전용

**검증 (2026-08-25)**
- `bash -n` 통과
- 실데이터 렌더 — 메뉴바 `오늘4/15` 유지(카운터 정직), 본 목록 11줄, 접힌 줄 1개 + 서브메뉴 5줄(안내 1 + 완료 4)
- 완료 취소 경로 = 각 완료 항목 라인이 `todoy.sh done {id}` 토글. 중첩 서브메뉴를 안 쓰므로 SwiftBar 중첩 지원 여부에 의존하지 않음
- ⚠️ 미검증 — **메뉴 실물 육안**(SwiftBar 드롭다운은 클릭으로만 열려 아리공이 못 본다). 피터공 확인분
- 분기 3종 샌드박스 실측(스텁 `render`로 픽스처 주입, 실데이터 무접촉) — ①전부 완료: `오늘 할 일 전부 완료` 회색 줄 + 접힌 줄만 ②0건: `(할 일 없음)` 그대로, 접힌 줄 안 뜸 ③완료 0건: 접힌 줄 안 뜸 + ACTIVE 파랑볼드·`⏸` 서브 정상

**남은 것 (별건)** — `carried`가 참/거짓뿐이라 「한 번 넘어옴」과 「닷새째 밀림」이 구분되지 않는다. 원래 날짜를 달면 3일+ 밀린 항목에 표시를 붙일 수 있고 DN 이월 3일 스캔 규칙과 같은 축이 된다. 데이터 포맷 변경이라 굿모닝/굿바이 연동까지 같이 봐야 함.
