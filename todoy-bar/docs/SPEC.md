## todoy-bar — 기술 명세 (SPEC)

> 코드보다 먼저. 변경 시 이 문서 먼저 갱신(선문후코).

### 한 줄

오늘 할 일 체크리스트 메뉴바 앱. now-bar(현재형)의 짝 = 계획축(오늘). 굿모닝 세팅 / ACTIVE 선택 / 횟수·시간 카운팅 / 완료 체크 / 굿바이 이월.

### 결정 (2026-06-02, 피터공)

- 이름 = **todoy-bar** (today + todo)
- DN "오늘 할 일"과 **독립** (동기화 안 함)
- now-bar와 **별도** 앱 (ACTIVE↔status 통합 안 함, 추후 가능성만)

### 데이터 모델

- 위치: `_dev/todoy-bar/data/YYYY-MM-DD.json` (날짜 단위 파일)
- 형식: 항목 객체의 JSON 배열

#### 날짜 경계 = 새벽 4시 (2026-08-12 도입)

`TODAY`는 자정이 아니라 **오전 4시**에 넘어간다. 구현은 `date -v-4H +%F` — 현재 시각에서 4시간 뺀 날짜.

- 00:00~03:59의 작업은 **아직 어제**로 들어간다. 피터공이 자정을 넘겨 일하는 날이 잦고, 그때 체크하는 항목은 어제 일의 연장이지 새 날의 시작이 아니다.
- **경계는 «그 시각에 도는 무엇»이 아니라 «지금이 몇 시냐를 계산하는 식»이다.** 4시에 돌 크론도 넘겨야 할 타이머도 없다. 그래서 4시에 컴퓨터가 꺼져 있었어도, 5시에 켜서 호출하면 그 자리에서 계산돼 정상 동작한다. 굿바이 시점 리셋·4시 크론 같은 «순간에 돌아야 하는» 설계를 택하지 않은 이유가 이것이다(컴 꺼짐·창 죽음에 넘김을 놓친다).
- 해외 체류 시에도 이 오프셋은 유지하고, 필요하면 `TZ`만 바꾼다.

> 배경: 2026-08-12 굿모닝에서 이월이 통째로 끊겼다. 직접 원인은 아래 «읽기는 쓰기를 하지 않는다»였고, 그 조사에서 자정 경계 자체가 피터공의 하루와 어긋나 있다는 것이 같이 드러났다.

#### 읽기는 쓰기를 하지 않는다 (2026-08-12)

`render`는 데이터 파일을 **만들지 않는다.** 없으면 `[]`를 출력만 한다.

플러그인이 5초마다 `render`를 부르므로, `render`가 파일을 만들면 **화면을 그리는 코드가 데이터를 만들고 그 데이터가 다음 동작의 조건을 바꾼다.** 2026-08-12 00:00:00에 렌더가 돌아 빈 오늘 파일이 태어났고, 아침 `setup`이 「파일이 이미 있음」으로 읽어 이월 12건을 건너뛰었다. SwiftBar가 자정까지 살아 있어야 터지는 사고라, **SwiftBar 안정성이 올라갈수록 더 자주 난다**(굿모닝 재시작 규칙 도입이 이를 앞당겼다).

```json
[
  {
    "id": "i12345",          // 유니크 id
    "text": "AI리터러시 시나리오 3개 초안",
    "done": false,           // 완료 여부
    "active": false,         // 지금 작업 중(ACTIVE) — 한 번에 하나만 true
    "switches": 0,           // 이 항목을 ACTIVE로 켠 횟수
    "seconds": 0,            // 누적 작업 시간(초). active 구간이 끝날 때 정산
    "active_since": null,    // 현재 active면 켠 시각(epoch초), 아니면 null
    "carried": false,        // 어제에서 이월됐으면 true (선택)
    "carried_from": null,    // 최초 등장 날짜 YYYY-MM-DD (선택, 2026-08-28)
    "dropped": false,        // 오늘 안 하기로 뺐으면 true (선택, 2026-08-28)
    "dropped_at": null       // 뺀 시각(epoch초)
  }
]
```

- **시간 누적 규칙**: active로 켜는 순간 `active_since = now(epoch)`, `switches += 1`. 끄거나 다른 항목으로 전환하거나 완료하면 `seconds += now - active_since`로 정산하고 `active=false, active_since=null`. 현재 active 항목의 표시 시간 = `seconds + (now - active_since)` (라이브 계산, render에서 `live_seconds`로 제공).
- **단일 ACTIVE**: activate 시 다른 모든 항목을 정산·비활성. 같은 항목을 다시 누르면 토글 off(정산).

### 컴포넌트

1. **`todoy.sh`** — 상태 변경 헬퍼 (절대경로 호출 → settings allowlist 매칭)
   - `setup` — 직전 날짜 파일의 미완료 항목을 상태 초기화해 이월(carried=true, `carried_from` 승계). **dropped 항목은 이월하지 않는다**(2026-08-28). 굿모닝용. **멱등** — 오늘 파일이 이미 있어도 돈다. 오늘 목록에 **같은 `text`가 없는 것만** 덧붙이므로 두 번 이상 돌려도 중복이 생기지 않는다.
     - ⚠️ 조건이 「오늘 파일이 없으면」이던 시절(~2026-08-11)엔, 오늘 파일이 먼저 생겨 있기만 하면 이월이 통째로 죽었다. 실제로 묻고 싶은 것은 **「이월을 아직 안 했는가」**인데 둘이 대개 같아서 안 걸렸다. 파일을 먼저 만들 수 있는 손은 렌더만이 아니다 — 굿모닝 전에 메뉴바에서 항목을 하나 추가해도 같은 문이 열린다.
     - `prev` = 오늘 파일을 뺀 나머지 중 가장 최근 날짜. 하루를 통째로 건너뛰어도(컴 꺼짐 등) 그 전날에서 이월된다.
   - `add "텍스트"` — 항목 추가
   - `add-dialog` — osascript 입력창 띄워 add (메뉴바에서 직접 입력)
   - `activate <id>` — 단일 ACTIVE 토글 + 시간 정산 + switches 카운트
   - `done <id>` — 완료 토글 (켜져 있으면 정산)
   - `drop <id>` — 「오늘 안 함」으로 뺀다(`dropped=true`). 이월·진행률·본 목록에서 빠지고 데이터에는 남는다. **완료 항목은 거부(exit 1).** 상세 → §빼기
   - `undrop <id>` — 되돌린다
   - `carryover` — 미완료 항목 텍스트 목록 출력. 굿바이용. **dropped 제외**
   - `render` — 현재 시각 기준 live_seconds 계산한 JSON 출력 (플러그인이 읽음)

2. **`swiftbar-plugins/todoy-bar.5s.sh`** — SwiftBar 메뉴바 플러그인 (5초 갱신)
   - 메뉴바: ACTIVE 항목 있으면 `▸ {텍스트} {누적시간}`, 없으면 `▸ todoy {완료}/{전체}`
   - 드롭다운: 항목마다 `☐/☑ {텍스트} ×{switches} {시간}`(텍스트 체크박스로 완료 상태 표시). **메인 클릭 = ACTIVE(지금 작업으로)**. 서브메뉴(`--`)에 `☑ 완료로 표시`(완료 토글) + ACTIVE면 `⏸ 지금 작업 해제`. ACTIVE 항목은 파란색+볼드(`md=true` 마크다운), 완료 항목은 초록색(`#009443`, 끝난 것 표시).
   - ⚠️ SwiftBar 메뉴 항목은 한 줄 전체가 단일 클릭 영역 → "체크박스 칸만 따로 클릭"은 불가. 그래서 메인=ACTIVE, 완료=서브로 분리(2026-06-02 피터공 정정). `checked=true`는 SwiftBar가 빈 체크칸을 안 그려서 텍스트 `☐/☑`로 대체.
   - **완료 항목은 지우지 않고 접는다 (2026-08-25 도입)**: 미완료를 먼저 다 그리고, 완료가 1건 이상이면 구분선 뒤에 `☑ 완료 {N}건` 한 줄을 두고 그 서브메뉴(`--`)에 완료 항목들을 넣는다. 클릭 = 완료 취소(`done` 토글). 서브메뉴 첫 줄에 회색 안내 `클릭하면 완료 취소`.
     - 미완료가 0건이고 전체가 1건 이상이면 목록 자리에 `오늘 할 일 전부 완료` 회색 한 줄.
     - ⚠️ **이건 표시만 접는 것이지 데이터를 덜어내는 게 아니다.** 하루치 JSON은 「메뉴바에 보이는 것」과 「그날의 기록」을 겸하고, 완료 항목은 진행률 `오늘{완료}/{전체}`의 **분자**다. 그래서 완료분을 파일에서 빼면 목록은 짧아지지만 카운터가 `0/N`이 되어 "오늘 뭘 했다"는 신호가 같이 사라진다(2026-08-25에 실제로 4/15 → 0/11로 겪음). **`archive` 같은 「하루치 파일에서 덜어내는」 명령은 만들지 않는다** — 그건 보기를 고치는 게 아니라 기록을 깎는 것이다.
     - 배경: 8/25에 「완료된 것 아카이브해 달라」는 요청이 왔는데, 목록이 길었던 진짜 원인은 완료분이 아니라 **15건 전부가 8/24에서 통째로 넘어온 것**이었다(오늘 새로 넣은 항목 0). 보기 문제와 이월 문제가 한 증상으로 뭉쳐 있었고, 접기는 앞엣것만 닫는다. 이월 쪽(`carried`가 참/거짓뿐이라 「한 번 넘어옴」과 「닷새째 밀림」이 구분 안 됨)은 별건. → **2026-08-28에 닫았다**: 빼는 명령이 없던 것이 진짜 구멍이었다(§빼기) + `carried_from`으로 나이를 단다(§이월 나이).
   - `＋ 할 일 추가`(add-dialog), 데이터 폴더 열기, 새로고침

#### 빼기 — `drop` / `undrop` (2026-08-28, 피터공)

**요청** — 피터공: *"선문후코로 기능 넣어주자."* 발단은 *"도대체 뭘 하는 건지. 왜 오늘 아이템으로 20개나 있는 것인지."*

**무엇이 없었나.** 항목을 「오늘 안 한다」고 빼는 동작이 도구에 없었다. 있는 것은 `done`(했다)뿐이라, 빼려면 **안 한 일을 완료로 거짓 체크**하거나 JSON을 직접 편집해야 했다. 그런데 굿모닝 스킬 2.6단계 2번은 *"이월된 항목을 피터공과 함께 본다 — 오늘도 할지, 뺄지"*이고, 그 문서가 *"뺄 항목은 그날 안 하면 자연 소멸"*이라고 적어 두었다. **소멸하는 경로는 없다** — `setup`은 미완료를 조건 없이 전부 이월한다. 문장이 그 자리를 설명해 버려서 명령이 없는 것이 정상으로 보였고, 목록은 8/22 9건 → 8/27 21건이 됐다.

**지우지 않고 표시한다.** `dropped: true`를 달아 데이터에는 남기고 **렌더·이월·진행률에서만 뺀다.** 8/25 「완료 항목 접기」와 같은 원리다 — 하루치 JSON은 「메뉴바에 보이는 것」과 「그날의 기록」을 겸하므로, 파일에서 덜어내면 보기는 짧아지고 기록이 깎인다. 「오늘 무엇을 안 하기로 했는가」도 그날의 사실이다.

**데이터**

```json
{
  "dropped": false,        // 오늘 안 하기로 뺐으면 true (선택, 없으면 false)
  "dropped_at": null       // 뺀 시각(epoch초). undrop 시 null로 되돌림
}
```

**명령**

- `drop <id>` — `dropped=true`, `dropped_at=now`. `active==true`면 **시간을 정산하고**(`seconds += now - active_since`) `active=false, active_since=null`.
  - ⚠️ **`done==true`인 항목은 거부한다**(exit 1, 안내 출력). 완료는 진행률의 **분자**이고 drop은 「안 한다」라서 둘은 배타적이다. 완료를 빼고 싶으면 먼저 `done`으로 완료를 취소한다.
- `undrop <id>` — `dropped=false`, `dropped_at=null`. 오늘 목록으로 되돌린다.
- `render` — dropped 항목도 **그대로 출력한다.** 거르는 일은 표시 층이 한다(플러그인이 접힌 줄을 그리려면 데이터가 필요하다).
- `setup` — 이월 대상에서 제외: `select(.done==false)` → `select(.done==false and (.dropped != true))`. **이것이 이 기능의 핵심이다.**
- `carryover` — 굿바이 보고에서도 제외(같은 조건).

**진행률 — dropped는 분모에서도 빠진다.** 메뉴바 `오늘{완료}/{전체}`의 전체 = `dropped != true`인 항목 수. 안 하기로 한 것은 진행률의 대상이 아니다. 8건 중 1건을 빼면 `오늘0/7`.

**표시 (플러그인)**

- 각 항목 서브메뉴에 `✕ 오늘 안 함` 한 줄 추가(`☑ 완료로 표시` 아래). **이것이 주 트리거다** — 빼는 순간이 굿모닝 하루 한 번밖에 없었던 것이 목록이 분 직접 원인이라, 그 항목을 보는 순간 뺄 수 있어야 한다.
- 본 목록은 미완료 **중 dropped가 아닌 것**만 그린다.
- dropped가 1건 이상이면 완료 접힌 줄 **아래**에 `✕ 뺀 항목 {N}건` 한 줄 + 서브메뉴(`--`)에 항목들. 클릭 = `undrop`. 서브메뉴 첫 줄에 회색 안내 `클릭하면 오늘 목록으로 되돌립니다`.
- 회색(`#888`)으로 그린다 — 완료 초록(`#009443`)·ACTIVE 파랑(`#1100ff`)과 갈린다.

**⚠️ 조용히 증발하는 자리 둘 — 여기가 이 변경의 진짜 위험이다**

이 도구에는 「목록에 없으면 삭제」로 판정하는 곳이 둘 있다. dropped를 화면·노트에서 빼기만 하면 그 둘이 **데이터에서도 지운다.**

1. **`sync.py`** — 3-way merge의 존재 판정은 *"base 대비 한쪽에서 사라지면 삭제 반영"*이다. dropped 항목을 미러 노트에 안 쓰면 「노트에서 사라짐」으로 읽혀 json에서 제거된다. → **sync는 dropped 항목을 아예 다루지 않는다**: 노트에 쓰지도 않고(`render_lines` 제외), 병합 대상에서도 빼고(`merge` 진입 전 분리), 결과 배열 끝에 **원본 그대로 되붙인다.** base 스냅샷에도 넣지 않는다.
2. **편집창(`edit.py` / `edit_server.py`)** — `build_saved(original, rows, [])`는 클라이언트가 보낸 `rows`로 배열을 **재구성**한다. 편집창이 dropped를 안 그리면 저장하는 순간 사라진다. → **`build_saved`가 원본의 dropped 항목을 무조건 보존**해 결과 배열 끝에 붙인다. 편집창 UI는 v1에서 손대지 않는다(dropped를 그리지 않는다).

**이 명령이 답하지 않는 것**

- **다음 날 굿모닝이 같은 항목을 다시 `add`하는 것은 못 막는다.** `drop`은 이월만 끊는다. 재유입은 별건이고(중복 검사가 이월에만 걸린다), 판단은 아리공이 DN을 보고 한다.
- **`dropped`는 날짜를 넘기지 않는다.** 하루치 파일 안의 사실이라, 내일 파일에는 그 항목 자체가 없다.

#### 이월 나이 — `carried_from` (2026-08-28)

**무엇이 없었나.** `carried`가 참·거짓뿐이라 **「어제 넘어옴」과 「열흘째 밀림」이 화면에서 똑같이 보인다.** 8/28에 특허청 건이 10일째인 것을 알아내려고 8월 JSON 28개를 전수로 훑어야 했다. DN에는 「이월 3일 스캔」 규칙이 이미 있는데 todoy에는 잴 값이 없었다.

**데이터**

```json
{
  "carried_from": "2026-08-18"   // 이 항목이 처음 등장한 날짜 (선택)
}
```

- `setup`이 이월할 때: 이전 항목에 `carried_from`이 **있으면 그대로 승계**하고, 없으면 **`prev` 파일의 날짜**를 넣는다. 승계이므로 매일 이월돼도 최초 등장일이 유지된다.
- `add`로 새로 넣는 항목에는 붙이지 않는다(오늘이 최초라 나이가 0).
- ⚠️ **소급하지 않는다.** 기존 파일에 `carried_from`이 없는 항목은 내일 첫 이월에서 어제 날짜를 받는다. 과거를 되짚어 채우려면 전수 스캔이 필요한데, 그 값은 「오늘부터 며칠 밀렸나」를 재는 데 쓰이므로 소급 이득이 작다.

**표시** — 나이가 **3일 이상**인 항목만 텍스트 뒤에 회색 ` +{N}일`. 전부에 붙이면 시끄럽고, 3일은 DN 이월 스캔과 같은 선이다. 나이 = 오늘(4시 경계 기준) − `carried_from`.

### 옵시디언 미러 싱크 (2026-07-06, sync.py)

- **목적**: 아이폰에서 todoy를 쓰고 싶음 → 옵시디언 싱크(폰↔맥, 맥 꺼져도 폰끼리 됨) 위에 노트↔json 파싱 동기를 얹어 "밖에서 폰으로, 맥 켜지면 병합". 맥 서버/클라우드 불필요.
- **미러 노트**: `<vault>/_init/todoy — 오늘 할 일.md`, `### YYYY-MM-DD` 섹션 아래 체크박스 목록. 미완료 먼저·완료 뒤로 재정렬.
- **항목 추적**: 각 줄 끝 `<!-- t:iXXXX -->` (옵시디언 읽기 모드에서 숨김). 폰에서 id 없이 새 줄 추가 → sync가 id 부여. 텍스트를 고쳐도·지워도 id로 추적.
- **3-way merge**: `data/.sync-base-YYYY-MM-DD.json`(지난 sync 스냅샷 `[{id,text,done}]`) 대비 노트·json 각각의 변경(추가·삭제·완료토글) 판정 후 병합.
  - done 충돌(양쪽 다 토글): **노트(폰) 우선**
  - 텍스트: 노트 우선
  - 존재: base 대비 한쪽에서 사라지면 삭제 반영 / base에 없던 신규는 양쪽 유지
  - json 고유 필드(active·switches·seconds·active_since·carried)는 병합 중 보존. 노트엔 텍스트+완료여부만.
  - **부트스트랩**: id 없는 노트 줄은 먼저 텍스트로 미사용 json 항목과 매칭(첫 sync에 중복 생성 방지), 없으면 신규.
- **명령**: `todoy.sh sync` (= `sync.py`), `sync --dry`(미리보기). 변경 있을 때만 파일 write(편집 중 덮어쓰기 완화).
- **전제**: 아이폰 옵시디언 싱크가 정상이어야 밖에서 작동(이건 별개 정비 사항). sync.py는 맥 안에서 노트↔json만 담당.
- **검증(2026-07-06)**: 노트↔메뉴바 추가·완료토글·삭제 4방향 수동 테스트 통과.
- **자동화(선택)**: launchd 주기 실행으로 무인 동기. 미도입 시 수동 `todoy.sh sync`.

### 편집창 (2026-07-10, 피터공)

- **배경**: SwiftBar 드롭다운은 macOS 네이티브 메뉴 → 항목 클릭 1회마다 메뉴가 닫힘(OS 동작, SwiftBar에서 못 막음). "여러 개 몰아서 편집·추가하고 내가 닫는" 흐름은 드롭다운이 아니라 진짜 창이 필요. 기존 `add-dialog`(osascript 단일 입력)의 확장판.
- **형태 결정(피터공)**: 빠른 유틸 창.
  - ~~1차: Tkinter(`edit.py`)~~ — **폐기(2026-07-10)**. macOS 시스템 파이썬의 Apple Tk 8.5.9가 레티나에서 Label·Entry 텍스트를 렌더하지 못함(버튼 등 네이티브 위젯만 그려짐). 리사이즈 리드로우 우회책도 실패. 새 Tk(8.6)는 brew 설치 필요 → 설치 없이 가는 게 낫다.
  - **2차 채택: 로컬 웹 창(`edit_server.py`)** — 파이썬 `http.server`가 127.0.0.1에 한 페이지를 띄우고, Chrome 앱모드 창으로 열어 편집. 렌더 100% 신뢰(그냥 HTML/CSS). 설치 불필요. 저장 로직(정산·id·삭제)은 `edit.py`의 순수함수(`load`/`build_saved`/`save`) 그대로 import해 재사용.
- **컴포넌트**:
  - `edit.py` — 순수 로직 모듈: `load()`·`build_saved()`·`save()`·`settle_done()`·`new_id()` + `--selftest`. GUI 없음(Tk 폐기).
  - `edit_server.py` — 오늘 파일을 읽어 HTML 페이지에 항목 embed → 브라우저 창.
  - 항목마다 한 줄: `[☐/☑ done]` 체크박스 + 텍스트 입력칸 + `✕` 삭제.
  - 하단 `＋ 새 항목` 입력칸(Enter 또는 추가 버튼으로 줄 추가). 여러 개 연속 추가 가능.
  - `[저장하고 닫기]`(주 버튼) / `[취소]`. 저장 시 `POST /save`(items JSON)→`build_saved`→`save` 후 `GET /quit`로 서버 종료 + `window.close()`.
  - 서버는 ephemeral 포트(127.0.0.1), 10분 유휴 자동 종료(창 방치 대비).
- **저장 시 데이터 규칙** (todoy.sh 로직과 정합):
  - 텍스트 수정: `.text`만 변경.
  - done 토글: 미완료→완료 전환 시 그 항목이 `active==true`면 시간 정산(`seconds += now - active_since`, `active=false, active_since=null`). 완료→미완료는 필드만.
  - 신규 항목: id = `i{난수}`(todoy.sh add와 동일 형식), 기본 필드 세트로 append.
  - 삭제: 배열에서 제거.
  - active·switches·seconds·active_since·carried는 위 규칙 외엔 **보존**(창 열려 있는 동안 active 항목 시간은 active_since로 계속 흐름).
- **호출/갱신**: `todoy.sh edit`가 `python3 edit_server.py`를 **detached**(`&`)로 띄움. 서버가 Chrome 앱모드로 창을 엶. 저장 시 `open -g "swiftbar://refreshplugin?name=todoy-bar.5s.sh"`로 즉시 갱신 시도(실패해도 5초 자동갱신이 커버).
- **메뉴 항목**: 드롭다운 하단 `✎ 편집창 열기 | bash=$TODOY param1=edit terminal=false`.
- **검증**: `edit.py --selftest`(JSON 로드→라운드트립·done 정산 로직 단위) + `edit_server.py`는 스크린샷으로 렌더 확인. 손맛(체크·추가·닫기 반영)은 피터공 라이브 확인.

#### 순서 변경 — 드래그 + 맨 위로 (2026-08-11, 피터공)

- **요청**: *"Task 순서를 drag해서 바꿀수 있으면 좋겠어. 위치 변경. 메뉴바 위치에서 어려우면 편집창에서는 될까?"*
- **메뉴바는 불가 — 구조적 한계.** SwiftBar 플러그인은 stdout 텍스트를 macOS 네이티브 NSMenu로 그린다. 메뉴 항목에는 클릭 이벤트만 있고 드래그 이벤트가 없다(SwiftBar가 아니라 OS 메뉴의 성질). 메뉴바에서 가능한 최선은 서브메뉴 `↑ 위로 / ↓ 아래로` 한 칸씩인데, **이번엔 넣지 않기로 했다**(피터공 선택 2026-08-11) — 여러 칸 옮기려면 반복 클릭이라 값이 낮다.
- **편집창에서 구현.** 그리고 이 변경은 **프런트엔드 전용**이다. 근거:
  - `build_saved(original, rows, [])`는 클라이언트가 보낸 `rows` **순서대로** out 배열을 쌓는다(edit.py:55~69).
  - `todoy.sh render`는 `map(...)`이라 정렬을 하지 않는다(todoy.sh:88~93).
  - 플러그인은 `.[]`를 배열 순서대로 그린다.
  - 즉 **JSON 배열 순서 = 편집창·메뉴바 표시 순서**가 이미 전 구간에서 성립한다. 저장 포맷·스키마·서버 핸들러 변경 0.
- **UI**:
  - 각 행 맨 앞에 **드래그 핸들 `⠿`**(회색, `cursor:grab`/드래그 중 `grabbing`). **핸들에서만 드래그가 시작된다** — 행 전체를 draggable로 두면 텍스트 입력칸의 커서 배치·드래그 선택이 막힌다. 구현: 평소 `row.draggable=false`, 핸들 `mousedown`에서 `true`, `dragend`에서 다시 `false`.
  - 각 행 끝(`✕` 왼쪽)에 **`⇧` 맨 위로** 버튼. 오늘 제일 먼저 할 것을 한 번에 올린다.
  - 드래그 중 피드백: 잡은 행 `opacity:.4`, 지나가는 행 위에서 **DOM을 즉시 옮겨** 실제 위치를 보여준다(별도 삽입선 인디케이터를 그리지 않는다 — 행이 직접 비켜서는 편이 읽기 쉽다).
  - 드롭 후 `items` 배열을 **DOM 순서로 재구성**한 뒤 `render()`로 다시 그린다.
- **핸들러는 index가 아니라 id로 바인딩한다.** 기존 `render()`는 `items[i]` 클로저를 썼는데, 드래그로 DOM 순서가 바뀌면 그 index가 실제 항목과 어긋나 **텍스트를 고치면 엉뚱한 항목이 바뀐다.** 그래서 체크·입력·삭제 전부 `items.find(x => x.id === id)`로 바꾼다(행에 `data-id` 부여). 순서 기능이 들어오는 순간 index 바인딩은 버그가 되므로 같이 고친다.
- **저장**: 기존 그대로 `POST /save` → `build_saved` → `save`. 순서는 payload 배열 순서로 전달된다.
- ⚠️ **sync.py와의 상호작용 (알려진 동작, 고치지 않음)**: `todoy.sh sync`는 결과 배열을 **노트 순서대로** 재구성하고(sync.py:112~), 노트는 `render_lines`가 **미완료 먼저·완료 뒤로** 쓴다(sync.py:84~91). 따라서 sync를 한 번 돌리면 **미완료끼리의 상대 순서는 보존되지만 완료 항목은 전부 아래로 내려간다.** 드래그로 정한 순서가 sync 후 그대로가 아닐 수 있다는 뜻인데, "완료된 건 아래로"는 오히려 원하는 동작이라 v1에서는 그대로 둔다. sync는 수동 호출이라 평소엔 마주치지 않는다.
- **검증**: `edit.py --selftest`(순서 무관 로직 회귀) + 창에서 드래그·맨 위로 후 저장 → `data/YYYY-MM-DD.json` 배열 순서와 메뉴바 표시 순서 육안 대조. 손맛은 피터공 라이브 확인.
