# SPEC — memory_hint (조건부 메모리 호출 훅)

> 2026-08-23 선문. 배경: [[요청.26.0823.1023-메이커에반5편검토]] C7 · [[부록.26.0823-메이커에반3편-컨텍스트]]
> 상태: **선문 완료, 코드 미착수**

## 0. 왜 만드는가

`MEMORY.md`에서 갈라 나온 분책 셋(`MEMORY_dev.md`, `MEMORY_text.md`, `MEMORY_projects.md`)은 매 세션 자동 로드되지 않는다. 인덱스를 가볍게 두려고 뺐고, 대신 **"해당 작업에 착수하면 아리공이 판단해서 Read한다"**로 두었다.

사람이 판단하는 규칙은 안 지켜진다. 8/16에 세션 체크리스트 상한을 사람이 지키는 형태로 두었다가 무너졌고, 그래서 `checklist_len.sh`로 **재는 주체**를 만들었다. 같은 교훈이 여기서도 성립한다.

**2026-08-23 실물 사례**: 아리공이 녹취 처리 체계를 제안하기 직전까지 `MEMORY_text.md`를 안 읽고 있었다. 피터공이 "지금 우리 어떻게 하고 있지?"라고 물어서 그제야 열었다. 안 물었으면 그 파일 안의 「행사장 녹취는 구간마다 품질이 다르다」와 「백도엔 왜 이 형식인가까지 준다」를 모르는 채로 체계를 세웠을 것이다.

피터공 진단(8/23)이 설계를 정했다.

> "기억이 필요한 단계 맥락으로 대화가 진행될 때는 당연히 잘하고, 엇나간 경우는 직접적 호출이 필요한 것이니 말이야."

그러면 고칠 수 있는 것은 기억이 아니라 **호출 조건**이다. 이 훅이 그 호출을 한다.

## 1. 범위

**한다**: 피터공 발화에 특정 낱말이 걸리면 해당 메모리 파일 경로를 아리공에게 한 줄로 알린다. 그리고 세션이 끝날 때 그 파일이 실제로 읽혔는지 확인해 안 읽혔으면 기록한다.

**안 한다**: 막지 않는다. 파일 내용을 주입하지 않는다(그러면 컨텍스트를 매번 먹어서 분책한 이유가 사라진다). 경로만 알린다.

**TM과 분리한다.** 같은 `UserPromptSubmit`에 걸리지만 `tm-hook.sh`에 얹지 않고 별도 스크립트로 둔다. 관심사가 다르고, 한쪽 버그가 다른 쪽을 죽이면 안 된다. TM 색 상태가 이 훅 때문에 멈추는 일은 없어야 한다.

## 2. 파일

| 경로 | 역할 |
|---|---|
| `_dev/scripts/memory_hint.sh` | 훅 본체. `hint`(UserPromptSubmit) / `audit`(Stop) 두 서브커맨드 |
| `_dev/scripts/memory_hint_rules.txt` | 낱말 → 메모리 파일 매핑. 코드와 분리해 손으로 고칠 수 있게 |
| `_dev/tm-bar/data/` 아님 | 로그는 `_dev/scripts/data/memory_hint.log` |

## 3. 매칭 규칙 — `memory_hint_rules.txt`

한 줄 = `{메모리파일}\t{정규식}`. 주석은 `#`.

```
MEMORY_text.md	녹취|전사|번역|클리핑|자막|STT|녹음
MEMORY_dev.md	배포|커밋|빌드|CloudFront|Lambda|CFN|스키마|_dev|_devhaus|디자인 미리보기
MEMORY_projects.md	슈테델|마니톡|Manifestalk|DMZ|오라마|words
```

- 매칭 대상은 **피터공 발화(`.prompt`)만.** 아리공 출력이나 툴 결과는 안 본다. 관측 내용이 훅을 흔들면 안 된다
- 여러 파일이 걸리면 전부 알린다. 최대 3줄
- 낱말은 앞으로 늘어난다. 규칙을 코드에 안 넣는 이유가 이것이다

## 4. hint — UserPromptSubmit

```
stdin(JSON) → .prompt 추출 → 규칙 대조 → 걸리면 stdout에 한 줄
```

출력 형식(아리공이 보는 것):

```
[memory] 이 발화에 「녹취」가 걸립니다 — memory/MEMORY_text.md 를 읽고 시작하세요.
```

- **`.prompt`가 없으면(다른 훅 이벤트) 조용히 exit 0.** 훅은 무해해야 한다
- 이미 이 세션에서 그 파일을 읽었으면 다시 안 알린다. 판정은 `transcript_path`의 jsonl에 그 파일명이 있는지로 한다(§6)
- 소음 상한: 한 세션에 파일당 1회

## 5. audit — Stop

세션이 멈출 때 그 세션에서 찌른 것이 실제로 읽혔는지 본다.

```
stdin(JSON) → .transcript_path → 그 jsonl에서 각 메모리 파일명 검색
```

- 찔렀는데 jsonl에 그 파일명이 한 번도 안 나오면 **놓친 건**으로 로그에 한 줄
- 로그 형식: `2026-08-23 14:02  D  MISS  MEMORY_text.md  (발화: "녹취 정리 좀…")`
- 읽혔으면 `HIT`로 남긴다. 비율을 나중에 볼 수 있어야 한다

> **이것이 C6(재설명 횟수 계측)을 대신한다.** "같은 설명을 또 했는가"는 피터공만 판정할 수 있어 기계가 못 센다. "이 세션에서 그 파일을 Read했는가"는 이진값이라 센다. **반복 대신 로드를 센다.**

## 6. 「읽었는가」 판정

`transcript_path`의 jsonl을 grep한다. Read 툴 호출이든 Bash `cat`이든 파일명 문자열이 대화에 나타나면 읽은 것으로 본다.

- 느슨한 판정이다. 파일명만 언급하고 안 읽었을 수 있다
- 그래도 이 방향의 오차가 안전하다. **거짓 HIT는 잔소리를 줄이고, 거짓 MISS는 잔소리를 늘린다.** 훅이 시끄러우면 사람이 훅을 끈다
- `hint`도 같은 판정을 쓴다(§4 중복 억제)

## 7. 배선 — `settings.local.json`

`UserPromptSubmit`과 `Stop` 배열에 **각각 한 항목씩 추가**한다. 기존 `tm-hook.sh` 항목은 건드리지 않는다.

```json
{"type":"command","command":"/Users/p.air15/Neo-Obsi-Sync/_dev/scripts/memory_hint.sh hint","timeout":5,"async":false}
{"type":"command","command":"/Users/p.air15/Neo-Obsi-Sync/_dev/scripts/memory_hint.sh audit","timeout":5,"async":true}
```

- `hint`는 **`async: false`**. 출력이 그 턴의 아리공에게 닿아야 하므로 비동기면 늦는다
- `audit`은 `async: true`. 로그만 쓴다
- 수정 전 `settings.local.json`을 `.bak.260823`으로 백업한다(7/9 색 훅 때와 같은 절차)

## 8. 검증 — 고치기 전에 붉게 뜨는 것부터 본다

8/18 훅 구멍 수정에서 배운 절차를 그대로 쓴다. **수정 전 빌드에서 검사가 실제로 실패하는지 먼저 확인한다.** 안 그러면 통과가 무엇을 뜻하는지 모른다.

| # | 검사 | 기대 |
|---|---|---|
| V1 | 훅 없는 상태에서 「녹취」 발화 → 힌트 안 나옴 | **실패해야 정상**(수정 전 붉음 확인) |
| V2 | `hint`에 `{"prompt":"녹취 정리 좀"}` 흘림 | `MEMORY_text.md` 한 줄 |
| V3 | `{"prompt":"오늘 날씨"}` | 출력 없음, exit 0 |
| V4 | `.prompt` 없는 JSON(Stop 페이로드) | 출력 없음, exit 0 |
| V5 | 두 낱말 동시(「녹취 배포」) | 두 줄 |
| V6 | 같은 세션에서 두 번째 「녹취」 발화 (이미 읽은 뒤) | 출력 없음 |
| V7 | `audit`에 읽은 세션의 transcript_path | `HIT` 한 줄 |
| V8 | `audit`에 안 읽은 세션 | `MISS` 한 줄 |
| V9 | 규칙 파일 없음 / 깨짐 | 조용히 exit 0 (훅은 무해) |
| V10 | 잘못된 JSON stdin | 조용히 exit 0 |

**실세션 확인**: V1~V10이 다 지나면 이 창에서 「녹취」가 든 발화를 한 번 하고 힌트가 실제로 뜨는지 본다. **자가 시뮬 통과는 배선 확인이 아니다** — 8/18에 matcher가 `Edit|Write`뿐이라 Bash로 만든 파일이 게이트에 안 보였던 것도 시뮬은 통과했었다.

## 9. 안 하기로 한 것

- **파일 내용 주입 금지.** 매 발화마다 메모리 본문이 들어가면 분책한 이유가 사라진다
- **차단 금지.** 훅이 작업을 막으면 급할 때 사람이 훅을 끈다. 끄면 영영 안 켠다
- **아리공 출력 매칭 금지.** 아리공이 「녹취」라고 쓰면 자기가 자기를 찌른다
- **`tm-hook.sh` 얹기 금지.** §1 참조

## 10. 열린 것

- 낱말 목록이 얼마나 자주 헛치는지는 돌려 봐야 안다. 로그의 HIT/MISS 비율과 별개로, **찔렸는데 관계없는 건**을 셀 방법은 아직 없다
- `MEMORY_projects.md` 쪽 낱말은 프로젝트가 바뀔 때마다 손봐야 한다. 규칙 파일을 손편집으로 둔 이유이자 약점
