## SPEC — vault_write.py (다중 창 동시 쓰기)

> 선문. 코드 전에 쓴다. 정본 방법론: [[개발 방법론 — 선문후코]] ②
> 요청: [[요청.26.0823.0858-스킬동시성]]

### 1. 무엇을 푸는가

한 맥북의 여러 창(A~F)이 `/goodmorning` · `/memento` · `/recall` · `/goodbye`를 동시에 돌릴 때, **서로의 쓰기를 통째로 덮는 사고**를 막는다.

원인은 하나다. Edit은 파일 전체를 읽어 전체를 다시 쓴다. 창B가 읽은 뒤 창C가 쓰고 그다음 창B가 쓰면, **창C의 수정이 사라지는 게 아니라 창B가 읽은 시점의 파일 전체가 되살아난다.** 창C의 작업이 없던 일이 된다.

중요한 전제 하나: **창들이 건드리는 자리는 서로 다르다.** 창B가 `Q76`을 고칠 때 창C는 `Q89`를 고친다. 의미상 충돌이 아니라 **기계적 충돌**이다. 그래서 자리를 지정해 쓰는 것만으로 병렬이 성립한다. 직렬화(순번 대기)가 아니다.

두 번째 원인은 타이밍이다. memento·goodbye는 쓰기를 백그라운드 에이전트에 넘기고 "완료"를 보고한다. 피터공이 보기엔 끝난 창이 실제로는 몇 분 더 쓰고 있어서, **겹치는 구간이 눈에 안 보인다.**

### 2. 이미 풀린 자리 = 설계의 본

`_dev/scripts/session_num.sh`가 세션 채번에서 같은 문제를 이미 닫았다(2026-08-06). mkdir 원자 락 + 파일 머리 기준 파싱 + 상단 삽입으로 7/29 race, 8/5 꼬리 채번, 삽입 위치 셋을 한 번에 잡았다. **이 문서는 그 패턴을 나머지 쓰기로 넓히는 것이지 새 발명이 아니다.**

### 3. 대상 파일 넷과 주소 단위

| 별칭 | 파일 | 주소 단위 | 쓰는 스킬 |
|------|------|-----------|-----------|
| `log` | `_클로드코드노트/클로드코드 세션 로그.md` (1MB) | `## 세션 {N}` 헤딩부터 다음 `## ` 전까지 | recall(생성, 이미 락) · memento · goodbye |
| `checklist` | `_init/세션 체크리스트.md` | 줄 끝 `<!-- P{n} -->` | memento · goodbye · goodmorning |
| `queue` | `_init/작업 큐.md` (950KB) | `##### Q{n} —` 헤딩 블록 | memento · goodbye |
| `dn` | `_init/_myJournal/{오늘}.md` | `###### {섹션}` 밑 append | goodmorning · memento |

**경로가 아니라 별칭으로 부른다.** 프롬프트에 절대경로를 적게 하면 오타 한 번에 엉뚱한 자리에 파일이 생긴다. 볼트에 0바이트 DB 껍데기 8개가 그렇게 생겼다(2026-07-28). 별칭은 스크립트 안에서 단 한 번 정의된다.

### 4. CLI

> **구현 언어는 python3다** (2026-08-23). `session_num.sh`는 bash지만 이쪽은 UTF-8 문자 수·행 단위 대조·본문 무결성 검사가 중심이라 셸로는 안전하게 못 짠다. 이 볼트는 이미 같은 이유로 «길이는 python3로 센다»를 규칙에 박아 두었다(한글 300자 줄이 `wc -c`로 864로 잡혀 헛경보가 났던 건). **락은 언어와 무관한 `mkdir` 디렉토리라 bash·python이 같은 락을 공유하는 데 문제가 없다.**

```
vault_write.py entry-fill    {N} {본문파일}            # log: 세션 N 엔트리 본문 «교체»
vault_write.py entry-append  {N} {줄}                  # log: 세션 N 엔트리 끝에 한 줄 «추가»
vault_write.py line-replace  {별칭} {UID} {새 줄}      # checklist: P-줄 교체
vault_write.py line-add      {별칭} {새 줄}            # checklist: 새 프로젝트 (UID는 스크립트가 발급)
vault_write.py line-remove   {별칭} {UID}              # checklist: 종결 프로젝트 제거
vault_write.py block-replace {별칭} {UID} {본문파일}   # queue: Q-섹션 교체
vault_write.py append-under  {별칭} {헤딩} {줄}        # dn: 섹션 밑 한 줄 추가
```

`entry-fill`은 memento·goodbye가 엔트리를 통째로 채울 때, `entry-append`는 **세션 중 실시간으로 «- 완료: {작업}» 한 줄씩 붙일 때**다(CLAUDE.md 「세션 로그 실시간 기록」). 둘을 가르지 않으면 실시간 append가 fill에 통째로 지워진다.

본문이 여러 줄인 것(`entry-fill` · `block-replace`)은 인자가 아니라 **파일로 받는다.** 셸 인용부호에 마크다운 본문을 넣으면 백틱·따옴표·줄바꿈에서 깨진다.

### 5. 락

- 파일별 `{경로}.lock` 디렉토리, `mkdir`로 획득(원자적). `session_num.sh`와 같은 방식.
- 1분 넘게 남아 있는 락은 죽은 것으로 보고 회수한다.
- 0.2초 간격 20회 재시도. 그래도 실패면 exit 2 + "어느 락인지" 메시지.
- `trap`으로 EXIT 시 반드시 해제.
- **대기는 실측 수십 ms다.** 창이 서로 기다리는 체감은 없다.
- 락 디렉토리 안에 **PID를 적는다.** stale 회수 전에 그 PID가 살아 있는지 본다. 맥북이 쓰기 도중 잠들면 «1분 넘었으니 죽었다»가 틀린 판정이 된다.

> 🚨 **락 경로를 `session_num.sh`와 반드시 통일한다 (2026-08-23 규명).** `session_num.sh`는 `_클로드코드노트/.session_num.lock`을 쓴다. vault_write가 `{파일경로}.lock`을 쓰면 **같은 세션 로그 파일에 서로 다른 락 둘이 걸려 상호 배제가 성립하지 않는다.** recall의 채번과 memento의 본문 채우기가 그대로 겹친다. **락은 파일 하나당 하나다.** `log` 별칭은 기존 `.session_num.lock`을 그대로 쓰고, `session_num.sh`도 같은 헬퍼를 부르게 고친다. 이걸 놓치면 이 SPEC 전체가 헛돈다.

### 6. 검증 — 매 쓰기마다

자기보고를 안 믿는다는 원칙([[개발 방법론 — 선문후코]] ③)을 쓰기에도 적용한다.

1. **쓰기 전 주소 매치 수를 센다.** 정확히 1개가 아니면 안 쓴다. 0개 = exit 1(엉뚱한 데 쓰지 않는다), 2개 이상 = exit 1(UID 중복은 이미 사고다).
2. **임시 파일에 완성본을 쓰고 `mv`로 교체한다.** 부분 쓰기 상태가 디스크에 남지 않게.
3. **쓴 뒤 그 주소를 다시 읽어 의도한 내용과 대조한다.** 다르면 exit 3.
4. **줄 수 변화가 예상 범위 밖이면 exit 3.** 950KB 파일이 통째로 날아가는 것을 여기서 잡는다.
5. **UTF-8 디코드를 확인한다.** 한글 3바이트 중 일부만 쓰이는 간헐 사고(세션195)가 이 자리에서 걸린다.

exit 코드는 갈라 놓는다: `0` 성공 / `1` 주소 없음·중복 / `2` 락 실패 / `3` 검증 실패. **"실패"가 한 가지로 뭉치면 원인을 못 짚는다.**

### 7. 안 하는 것 (명시)

- **옵시디언 싱크는 못 막는다.** 락은 이 맥북 안에서만 든다. Pro나 폰에서 같은 DN을 고치면 여전히 싱크 충돌이다([[feedback_dn_sync_race]]). 이 SPEC이 덮는 범위는 "한 맥북의 여러 창"이다.
- **같은 UID를 두 창이 동시에 쓰면** 나중이 이긴다. 락으로 못 푸는 진짜 충돌이다. 대신 덮어쓴 옛 줄을 `_dev/scripts/logs/vault_write.log`에 남겨 되찾을 수 있게 한다.
- **내용을 자동으로 요약하거나 줄이지 않는다.** `checklist_len.sh`와 같은 원칙: 재기만 하고 판단은 창이 한다.

### 8. 곁딸린 수정 — tm.sh `claim`

지금 `tm.sh slot`은 빈 글자를 알려줄 뿐 예약하지 않는다. 두 창이 동시에 부르면 같은 글자를 받는다(스킬 문서도 "제안일 뿐 예약이 아니다"라고 적어 두었다). `claim {SESSION_UUID}`를 추가해 **조회와 register를 한 락 안에서** 처리한다.

### 9. 백도는 유지한다 — 락이 생기면 안전해진다 (2026-08-23 수정)

**첫 안은 「백도를 빼고 전부 직도」였다. 한 걸음 지나쳤다.** 피터공 지적으로 바로잡는다: 백도가 거기 있는 이유에는 «오퍼스를 쓸 필요가 없는 일»이라는 것도 있다.

먼저 사실 확인. `memento/SKILL.md` §3은 "Agent 도구로 백그라운드 에이전트를 실행한다"고만 적었고 **모델 지정이 없다.** `.claude/agents/`에 정의도 없다(프로젝트·글로벌 둘 다). Agent 툴은 모델이 생략되면 부모를 상속하므로 **지금 백도도 오퍼스로 돈다.** 백도가 실제로 아끼는 것은 컨텍스트뿐이고, 모델 값은 안 아끼고 있다.

그리고 엉켜 있던 셋이 락으로 갈린다.

| 문제 | 무엇이 푸는가 | 백도와 상관있나 |
|------|--------------|----------------|
| race (서로 덮어씀) | `vault_write.py` 락 | **없다.** 메인이 쓰든 백도가 쓰든 같은 락을 통과한다 |
| 보이지 않는 창 | 임시파일+`mv` + 완료 마커 | 손실 위험이 아니라 "끝났나?" 질문으로 줄어든다. 백도가 중간에 죽어도 파일은 옛 판이거나 새 판이지 반쪽이 아니다 |
| 모델·컨텍스트 | 백도 **유지** + 싼 모델 고정 | 백도가 있어야 이득이다 |

**결론: 백도를 뺄 이유가 없다.** 빼려던 이유는 «몰래 쓰는 게 위험해서»였는데, 락이 그걸 무해하게 만든다. 대신 백도에 셋을 못박는다.

1. **프롬프트에서 Edit·Write를 금지하고 `vault_write.py`만 쓰게 한다.** 락 밖 쓰기를 원천 차단한다. 규칙을 적는 것으로는 안 지켜진다는 것이 이 볼트의 반복 교훈이라, 스킬 문구가 아니라 **에이전트 프롬프트의 명시 금지 + 도구 제한**으로 건다.
2. **모델은 고정이 아니라 «일 종류»로 가른다** (2026-08-23 피터공). 아래 §9-1.
3. **완료 마커를 남긴다.** 백도가 마지막에 `_dev/scripts/logs/memento_done_{세션N}` 을 찍고, 다음 `/recall`·`/goodbye`가 그것을 확인한다. "memento가 끝났는지"를 사람이 짐작하지 않게.

> 참고: 백도의 판단 몫은 원래도 작다. memento 스킬이 에이전트 프롬프트에 "한 일 목록 (구체적으로 — 에이전트는 대화 컨텍스트를 모름)"을 넣으라고 적어 두었다. 무엇을 쓸지는 메인이 지어서 넘기고 백도는 옮겨 적는다. 그래서 Sonnet으로 충분하다.

#### 9-1. 백도 모델 라우팅 — 두 갈래

모델은 백도 launch마다 주는 값이지 전역 설정이 아니다. 그래서 **일 종류로 가른다.**

| 갈래 | 기준 | 무엇이 여기 오나 |
|------|------|------------------|
| **Opus** | 판단이 결과를 바꾼다 | 코드(작성·수정·디버깅·배포 검증) · 집필(초안·번역·편집) · 분석(녹취 도출·자료 검토·교차 분석) · 탐구 노트 · 남의 산출물 검증 |
| **Sonnet** | 내용은 정해졌고 옮겨 적는다 | 세션 로그·작업 큐·DN 기록(memento·goodbye) · 노트 정리·이동·링크 갱신 · 정해진 틀 채우기 |

memento 백도는 두 번째다. 무엇을 쓸지는 메인이 지어서 넘기고 백도는 옮겨 적는다(스킬이 프롬프트에 "한 일 목록"을 다 넣으라고 적어 둔 이유다). 반대로 개발 백도는 첫 번째고, 여기서 Sonnet을 쓰면 **스펙을 문자대로 구현하거나 조용히 실패하는 쪽으로 미끄러진다**([[feedback_todo_item_not_literal_spec]] · [[feedback_collaborator_ui_spec_not_literal]]가 그 사고들이다).

**규칙 형태가 중요하다.** "판단해서 골라라"로 두면 무너진다. 체크리스트 800자 상한이 네 번 재발한 것이 정확히 그 형태였다([[feedback_index_line_length_cap]]). 그래서 갈라 둔다.

- **스킬 셋은 문구에 모델 값을 박는다.** memento·goodbye 스킬에 `model: sonnet`을 적어 둔다. 매번 판단할 일이 아니다.
- **그때그때 띄우는 백도만 위 표로 판단한다.** 일 종류가 매번 다르니 여기는 표가 맞다.
- 구현 시 이 표는 **CLAUDE.md 백도 섹션에도 한 줄로 올린다.** SPEC 안에만 있으면 볼트 노트 작업 세션에서는 안 읽힌다.

**⚠️ 결정 필요 — goodmorning 오늘의 낚시.** 볼트를 뒤지는 것은 기계인데 **무엇을 건질지와 "왜 읽을 만한지" 한 문단이 전부**다. 낚시의 목적이 «잊고 있던 생각을 마주하는 것»이라 고르는 눈이 결과를 통째로 좌우한다. **Opus 추천** — 하루 한 번이라 비용이 작고, Sonnet이 무난한 것을 골라 오면 낚시가 낚시가 아니게 된다. 피터공 판단 대기.

### 10. 단계

0. **작업 큐 Q-UID 백필** (§11) — 이게 먼저다. 주소가 없으면 스크립트가 절반을 못 짚는다
1. `vault_write.py` + `selftest.sh` (코드). 락 경로를 `session_num.sh`와 통일 (§5)
2. `.claude/agents/vault-writer.md` 신설(`tools: Bash, Read` · `model: sonnet`) → memento 3단계: 백도 **유지**, 이 에이전트로 교체 + `model: sonnet`(§9-1) + 완료 마커. 라우팅 표를 CLAUDE.md에도 한 줄
3. goodbye 동일
4. goodmorning DN 쓰기 교체 + `tm.sh claim`
5. **실측 둘**
   - 두 창에서 동시에 memento를 돌려 양쪽 UID가 파일에 살아 있는지 확인. 통과 문구가 아니라 **양쪽 UID가 파일에 실재하는 것**이 증거다
   - 백도가 Edit을 못 쓰는지 확인. 프롬프트에 금지만 적고 안 재면 또 새어 나간다

### 11. 선행 마이그레이션 — 작업 큐 분류 (필수)

**`vault_write.py`를 짜기 전에 이것부터 한다.** 실측: 활성 81개 중 **41개만 Q-UID 보유, 40개 없음**. Q 체계는 2026-08-11에 도입됐고 그 뒤 것에만 붙었다.

**첫 안은 「40개에 전부 UID 부여」였다. 방향이 틀렸다** (2026-08-23 피터공): *"너무 오래되어 포멧이 변하고 사용되지 않는 것에 앞으로를 맞추는 것은 내가 생각하는 방향은 아니지만, 아카이빙이 되는 것은 중요하지."*

**앞으로 쓸 것만 주소를 갖고, 안 쓰는 것은 찾을 수 있게 내린다.** 판정 근거는 추측이 아니라 대조다 — `_init/세션 체크리스트.md`의 활성 프로젝트(`P{n}`)와 큐 섹션을 맞춰 본다.

### 12. 이 변경이 새로 만드는 위험과 대응

| 위험 | 왜 생기나 | 대응 |

### 13. selftest 항목

- 두 프로세스가 동시에 **다른 UID**를 쓰고 둘 다 살아남는가
- 두 프로세스가 동시에 **같은 UID**를 쓰면 나중이 이기고 옛 줄이 로그에 남는가
- 없는 UID → exit 1이고 **파일이 한 바이트도 안 변하는가**
- 중복 UID → exit 1
- 헤딩 블록 교체가 **이웃 섹션을 같이 먹지 않는가** ([[feedback_splice_edit_eats_neighbors]]가 정확히 이 사고다)
- 한글 NFD 본문에서 도는가 ([[feedback_nfd_kfind]])
- 락 디렉토리를 강제로 남겨 두고 부르면 stale 회수가 도는가

### 14. 바꾼 뒤 — 무엇을 동시에 돌려도 되나

이 SPEC이 닫히면 이렇게 갈린다.

**동시에 돌려도 안전**
- 여러 창 `/recall` 동시
- 여러 창 `/memento` 동시 (**서로 다른 프로젝트일 때**)
- `/goodmorning` 도는 중 다른 창 `/recall`
- `/memento` 도는 중 다른 창 `/recall`
- 백도 여럿 동시 (각자 같은 락을 통과한다)

**되지만 조심**
- **같은 프로젝트를 두 창에서 동시에 memento**: 나중이 이긴다. 덮어쓴 옛 줄은 `logs/vault_write.log`에 남으니 되찾을 수 있다
- **옵시디언에서 DN·체크리스트를 편집하는 중 memento**: 옵시디언 버퍼가 이길 수 있다. 락 밖이다
- **다른 기기(Pro·폰)에서 같은 파일**: 싱크 충돌. 락은 이 맥북 안에서만이다

**여전히 하나만 — 락이 못 푸는 설계**
- **`/goodbye`는 마지막 창 하나에서만.** goodbye는 `for id in A B C D E F; do unregister; done`으로 **남은 창을 전부 내리고** `flush`로 그날 TM 로그를 확정한다. 다른 창이 살아 있는데 goodbye를 돌리면 그 창이 메뉴바에서 사라진다. 이건 쓰기 충돌이 아니라 «하루를 닫는다»는 의미라 락으로 풀 성질이 아니다
- **`/goodmorning`은 하루 한 번, 첫 창에서만.** DN을 만들고 작업 큐에서 «해야 할 일»을 뽑는다. 둘이 돌면 파일은 안 깨지지만 **항목이 두 벌 생긴다**

## 미결 — `append-under`가 중복을 안 거른다 (2026-08-31 발견)

세션 1054 memento에서 DN `오늘의 요청`에 **같은 요청 노트 링크가 두 줄** 들어갔다. 메인이 노트를 만든 자리에서 한 번 넣었고(즉시 등록 규칙), memento 백도가 「없으면 추가」 지시를 받고 한 번 더 넣었다.

- **백도 탓이 아니다.** 프롬프트에 *"이미 있으면 넣지 않는다"*라고 적었지만, **그 판정을 사람 말로만 걸어 두면 안 지켜지는 자리다.** `append-under`는 시키는 대로 붙일 뿐 같은 줄이 이미 있는지 안 본다
- 스킬 절차가 「메인이 즉시 등록」과 「백도가 누락 확인」을 둘 다 시키므로 **이 중복은 구조적으로 매번 날 수 있다**

**고칠 방향**: `append-under`에 「같은 줄이 그 섹션에 이미 있으면 아무것도 안 하고 exit 0」을 넣는다. 링크 한 줄은 멱등해야 하는 값이다. ⚠️ 다만 「같은 줄을 일부러 두 번 적는」 쓰임이 있는지 먼저 훑는다 — 세션 로그 `entry-append`는 같은 문구가 두 번 올 수 있으니 그쪽에 같은 규칙을 걸면 안 된다.

임시 조치: 8/31 DN의 중복 한 줄은 손으로 지웠다(원자적 교체). **손처리는 1회성이고, 두 번째는 코드로 간다.**
