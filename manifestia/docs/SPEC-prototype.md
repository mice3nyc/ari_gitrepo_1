## SPEC — Manifestia 1단계 프로토타입 (폰 단독)

> 선문후코 명세. 코드 작성 전 단일 소스. 1단계 = 플레이어 폰 한 대에서 게임 루프 3화면이 돌아가는 것까지. 서버·세션 코드·QR·멀티플레이·실시간 투표는 2단계.
> 상위 기획: [[Manifestia — 개발 착수 계획]] / 결정 로그: [[요청.26.0618.1453-Manifestia프로토타입스펙]]

#### 0. 범위

**1단계 (이 SPEC)**: 폰 단독. 캐릭터 선택 → 포스터 매칭(단어 획득) → 매니페스토 조립·제출 → 투표. 상태는 로컬 저장.

**비범위 (2단계 이후)**: 서버, 세션 코드, QR 프리필, 타인의 매니페스토(1단계 투표는 로컬 더미), 시간 모드(제한/무제한), 다국어 실제 전환(1단계는 구조만 깔고 한국어로 동작), 팀 공용 풀·선물.

#### 1. 아키텍처

- 클라이언트 단독 웹앱. 프레임워크는 풀스택 전환을 고려해 선택(신규 개발은 바닐라 제약 없음). 상태는 localStorage, prefix `mnf_proto_`.
- 데이터 두 갈래로 로드: `data/posters.json`(120 포스터) + `i18n/ko.json`(UI 텍스트).
- **2단계 대비**: 데이터 접근(포스터 조회·상태 저장)을 한 겹의 추상화 레이어로 감싼다. 2단계에서 localStorage → 서버 API로 교체할 때 화면 코드를 안 건드리게.

#### 2. 데이터 모델

**Poster** (posters.json, 120개):
```
{ poster_no, artist_ko, affinity:[유형...], 
  value_marks: { HEALER:{가치:bool×4}, TANKER:{...}, ILLUSIONIST:{...}, PROFESSOR:{...} },
  words: [ {slot:1~4, word_ko, type:"lexical"|"onomatopoeia"} ],   // 4슬롯, 전부 고유(480개 중복 0)
  text_ko }
```

**캐릭터 4유형**: HEALER(치유자) / TANKER(전사) / ILLUSIONIST(환영가) / PROFESSOR(교수).

**PlayerState** (localStorage):
```
{ character: 유형,
  inventory: [ {wordId, word_ko, fromPoster, slot} ],   // 복수 소지 X
  acquired: { poster_no: [획득한 slot...] },             // 재입력 시 없는 것만 주기 위한 기록
  manifestos: [ {id, status:"draft"|"submitted", wordIds:[...], text, submittedAt} ],
  score: number }
```

#### 3. i18n 구조

- 모든 UI 텍스트(버튼 라벨, 안내문, 에러, 화면 제목)는 **키로 분리**. 코드에 한국어 문자열 직접 넣지 않는다.
- `i18n/ko.json = { "btn.match":"매칭", "btn.submit":"제출", ... }`.
- **마스터 시트** `키 | 한국어 | 영어 | 독어` → 빌드가 언어별 json 추출. 디자이너는 시트만 보고 수정.
- 게임 데이터는 이미 `*_ko/en/de` 필드 분리됨. 1단계는 `_ko`만 사용.

#### 4. 화면 명세

##### 4.1 입장 / 캐릭터 선택
- **캐릭터 배정 방식 = 세션 파라미터** {자유 선택 | 진단형 | 팀 할당}. 세션(2단계) 발급 시 셋 중 하나 지정. 캐릭터는 포스터 매칭 규칙 자체라 입장의 첫 관문(DEV-007).
- **1단계는 자유 선택만 구현**: 캐릭터 4유형 중 플레이어가 직접 선택 → PlayerState 초기화. 진단형(취향 질문 2~3개)·팀 할당(팀 균형 자동 배분)은 2단계 세션 옵션으로 추가(자리만 비워둠).

##### 4.2 포스터 매칭
- 포스터 번호 입력 → posters.json lookup. 없는 번호면 에러 안내.
- **매칭 판정**: `stars = value_marks[내 캐릭터]의 true 개수`
  - `stars == 4` (100% 매칭): 그 포스터 4단어 **전부** 획득
  - `stars == 1~3` (부분 매칭): **랜덤 1단어** 획득 (이미 가진 슬롯은 후보에서 제외 = 재입력 시 없는 것만)
- **획득 처리**: inventory에 추가(복수 소지 X, 이미 있으면 skip), `acquired[poster_no]`에 슬롯 기록.
- **득점**: 단어 획득 시 +5 / 포스터 (DEV-012).
- **재입력**: 같은 포스터 무제한 재매칭. 이미 가진 단어는 안 주고, 소모돼 비어 있는 슬롯만 복구. (재획득 비용=쿨다운은 1단계 미적용, §8 잠정)

##### 4.3 매니페스토 쓰기
- 인벤토리 단어를 칩으로 표시 → 선택해 문장 슬롯에 순서대로 배치(조립). 단어를 어디 둘지가 핵심 UX.
- **작업중 저장**(draft) + **완성 목록**. 목록 화면에서 골라 이어 쓰거나 제출.
- **제출**: 사용한 단어를 inventory에서 **제거**(소모, status→submitted), 미사용 단어는 유지. 득점 +20.

##### 4.4 투표
- 1단계: 로컬 더미 매니페스토 풀(샘플 몇 개 + 본인 제출분)로 월드컵식 2지선다.
- **투표 클릭당 +1**. (투표받음 +5는 멀티플레이라 2단계, 1단계는 더미 표시만.)

#### 5. 단어 경제 (DEV-015 확정)

소모성(쓴 단어만 0, 미사용 유지) / 복수 소지 X(0·1) / 재입력 무제한 + 없는 단어만 복구 / 선물·교환 v1 제외(단어 480개 전부 유일해 나중 가치 큼).

#### 6. 득점 (DEV-012)

단어 획득 +5/포스터 · 매니페스토 제출 +20 · 투표 +1/클릭 · 투표받음 +5/표(2단계) · 콤보 +10(투표받을 때만, 2단계).

#### 7. 빌드 단계 (단계적 빌드)

- `build:data` — 엑셀/시트 → `posters.json` (merged 파이프라인 재사용, 120 포스터 펼침)
- `build:i18n` — 마스터 시트 → `i18n/{ko,en,de}.json`
- `build:app` — 클라이언트 번들
- 세 빌드를 분리해, 콘텐츠·번역·코드가 따로 갱신되게.

#### 8. 잠정값 / 피터공 확인 대기

- **소모 타이밍**: 매니페스토 제출 시 즉시 소모 (채택 잠정)
- **재획득 방식**: 1단계는 쿨다운 미적용, 재매칭 즉시 복구. 쿨다운(5분) vs 재매칭 택1은 서버 단계에서 확정
- **포스터 재입력 횟수**: 무제한 (잠정)
- **캐릭터 배정**: 1단계 자유 선택 확정 구현. 2단계 세션 파라미터로 {자유 선택 / 진단형 / 팀 할당} (School QR=팀 할당, 상시 플로어 QR=진단형 식)

#### 9. 디자인 단계 결정 (6/22 확정)

원형 아트워즈 UI 레퍼런스(`docs/REF-artworz-original-UI.md`)를 놓고 피터공 4건 확정. "다 추천대로 가보자."

1. **시작·결과 화면 둘 다 추가** → 7화면 확정: 시작 / 캐릭터선택 / 포스터매칭 / 단어주머니 / 매니페스토쓰기 / 투표 / 결과. (지금 빌드는 중간 4화면만 — 시작·끝 신설)
2. **단어주머니 = 별도 탭.** 하단 네비 독립 탭. "내 단어 가방" 소유감 + 현재 탭 구조와 정합. (원형은 문장제출 안 인라인이었으나 폰 단독에선 독립 탭 채택)
3. **흐름 = 자유이동.** 하단 네비로 화면 자유 이동. 폰 단독 + 축제 드롭인(비동기) 모드에 맞음. (가이드형 순차 강제는 2단계 School 동기 모드 세션 옵션으로 보류)
4. **디자인 톤 = 원형 "노란 폭발" 채택.** 평상=무채색(회색 배경+굵은 검은 테두리) / 완료·확인 순간=노란 배경+월계관 일러스트. 우리 B&W 하우스 톤 + 포인트 컬러 한 점.

5. **다국어 전환 = 독/영/한 3개국어, 런타임 토글.** UI 텍스트는 이미 키 분리(`i18n/`), 게임 데이터는 `*_ko/en/de` 분리됨. 실제 코드에서 언어 토글로 텍스트 테이블 교체.
   - **범위 구분(6/22 슈테델 명시)**: 슈테델 운영 배포는 **독/영만** 노출(축제 관객 대상). **한국어는 우리 개발·테스트용**(테스팅 데이터가 한국 데이터라 1차 한국어). 우선순위 독 > 영 > 한.
   - 토글 위치: 시작 화면에 DE·EN·KO 세그먼트(와이어프레임 반영). 슈테델 빌드는 KO 숨기고 DE 기본, 개발 빌드는 KO 포함.
6. **추후 탑재(프로토타입 이후)**: 슈테델 공식 폰트, 슈테델 로고 등 브랜드 자산. 현재는 페이퍼로지 + STÄDEL×놀공 텍스트 플레이스홀더로 둠.

**다음 단계 (와이어프레임 → 클로드디자인 보드)**: 7화면 흑백 HTML 와이어프레임 작성 → DesignSync(claude.ai/design) 보드에 카드로 push → 피터공 보드에서 비교·검토 → 확정 방향으로 실제 화면 코드.
